# Requirement sets are published to Confluence in order to be approved there

The lifecycle is draft → verified → validated → published (awaiting approval) → approved → retired or superseded. Sets are published once validated, and approvers sign off in Confluence, so approval is recorded in the system of record rather than in the workspace. The workspace tracks status up to `published`; anything later is read from Confluence. We rejected approving in the workspace first, because stakeholders already review and approve in Confluence and a second approval trail would drift.
